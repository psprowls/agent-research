# Guidance Index Pages — Design

**Date:** 2026-06-09
**Status:** Approved
**Approach:** Extend `wiki_io/update_index.py` (Approach A)

## Problem

Guidance pages (`wiki/guidance/<topic>/<slug>.md`, written by the skill-ingest
branch) have no index anywhere: `guidance` is not in
`update_index.CATEGORY_INDEX_FILES`, so no per-folder sub-index is generated,
and it is not a `CURATED_LANES` entry in `index_generator.py`, so guidance is
invisible from the main `wiki/index.md`. An agent (or human) browsing the wiki
cannot discover guidance content without listing the directory.

## Goal

Two levels of auto-generated index:

1. `wiki/guidance/index.md` — lists the topics under `guidance/`.
2. `wiki/guidance/<topic>/index.md` — lists the guidance pages in that topic.

Plus a navigational `## Guidance` section in the main `wiki/index.md`.

## Decisions (from brainstorming)

- **Ownership:** fully auto-generated, regenerated by `update_index()` after
  every ingest — same lifecycle as `concepts/index.md` et al. Hand edits are
  overwritten; the files are machine-owned.
- **Main index:** a small `## Guidance` section with one link per topic +
  a lead link to `guidance/index.md`. NOT a full curated lane (per-item
  listings would bloat the main index as guidance grows).
- **Entry detail:** wikilinked title + summary + impact suffix:
  `- [[guidance/<topic>/<slug>|Title]] — <summary> _(<impact>)_`.
- **Placement:** rendering logic lives in `wiki_io/update_index.py` next to
  its flat category-index siblings (rejected: a new `guidance_io.index`
  module — would pull wikilink rendering into a pure-primitives package;
  rejected: scan-time generation in `index_generator.py` — wrong cadence,
  guidance pages are written by ingest, not scan).

## Output format

### `wiki/guidance/index.md` (root index)

Frontmatter: `title: Guidance Index`, `category: index`, `summary`, `updated`
(same shape as `render_category_index` emits today). Body: H1, auto-generated
banner line, then one bullet per topic, sorted alphabetically by topic slug:

```markdown
- [[guidance/deep-agents/index|Deep Agents]] — 9 pages
- [[guidance/expo/index|Expo]] — 1 page
```

Topic display name derives from the directory name: `deep-agents` →
"Deep Agents" (hyphens/underscores to spaces, title case — same derivation as
`infer_title`). Page count counts non-`index.md` `.md` files in the topic dir.
Singular/plural: "1 page" / "N pages".

### `wiki/guidance/<topic>/index.md` (per-topic index)

Same frontmatter shape (`title: <Topic> Guidance Index`). Body: H1, banner,
then one bullet per page, sorted by title case-insensitively (matching
existing sub-index sort):

```markdown
- [[guidance/deep-agents/skill-md-requires-yaml-frontmatter|SKILL.md Requires YAML Frontmatter]] — Every SKILL.md must open with a YAML frontmatter block carrying name and description, or it will not register as a skill. _(high)_
```

`title`, `summary`, and `impact` are read from each page's frontmatter via
the existing `parse_frontmatter` regex (all flat keys — the regex-subset
parser handles them; the nested `triggers:` block is ignored, which is fine).
Missing `summary` → omit the ` — …` segment; missing `impact` → omit the
`_(…)_` suffix.

## Generation logic — `wiki_io/update_index.py`

New function `update_guidance_indexes(wiki: Path) -> None`, called from
`update_index()`:

1. If `wiki/guidance/` does not exist or contains no topic dirs with content
   pages, write nothing and return.
2. For each immediate subdirectory of `guidance/` (skipping dotfiles):
   collect non-`index.md` `.md` files; if none, skip the topic (no index
   written for empty topic dirs).
3. Render and write `guidance/<topic>/index.md` for each topic, then
   `guidance/index.md`. Writes are unconditional `write_text` (matching the
   existing category-index behavior — no byte-compare).

Loose `.md` files directly under `guidance/` (not in a topic dir) are not
expected (the ingest writer always nests under a topic) and are ignored by
the renderer.

Since `update_index()` already runs in every ingest tail — including the
skill branch that writes guidance pages — the indexes refresh exactly when
guidance content changes. No new call sites.

**Accepted gap:** deleting an entire topic directory's content leaves its old
`<topic>/index.md` ungarbage-collected, and a fully emptied `guidance/` tree
leaves a stale root index. Consistent with the rest of the system (nothing
GCs removed pages today); manual cleanup, lint may flag staleness.

## Exclusions — keeping index files out of content scans

- `guidance_io.paths.list_pages`: **change required** — exclude `index.md`
  from the topic-dir glob (currently returns all `*.md`).
- `update_index.scan_vault` and `index_generator._scan_curated_lane`: no
  behavior change needed — both already skip any file *named* `index.md` via
  their `GENERATED_FILES` name checks. Still, add `guidance/index.md` to both
  `GENERATED_FILES` sets explicitly for documentation value (the per-topic
  paths are dynamic and rely on the name check, which both scanners apply).
- `backlink_index.py`: untouched. Generated index pages contain no
  `[[entities/...]]` links, so the backlink scan over `guidance/` is a
  harmless no-op for them — same as the existing `sources/index.md`.
- Lint: guidance index pages carry `category: index`, not
  `category: guidance`; nothing validates them against the guidance-io
  schema (that validation runs only at ingest write time).

## Main index — `wiki_io/index_generator.py`

New `## Guidance` section rendered after `## Sources` and before `## Work`:

```markdown
## Guidance

- [[guidance/index|All guidance topics]]
- [[guidance/deep-agents/index|Deep Agents]] — 9 pages
- [[guidance/expo/index|Expo]] — 1 page
```

- Data source: filesystem scan of `wiki/guidance/` (like the curated lanes),
  no graph involvement.
- Omitted entirely when there are no guidance pages (empty-section omission,
  D-08 pattern).
- Guidance pages do **not** count into the banner's "curated pages" number
  (banner semantics unchanged); the section is purely navigational.

**Accepted cadence wrinkle:** the main index is scan-owned (full rewrite,
D-02), so a brand-new topic appears in `guidance/index.md` immediately after
ingest but in the main `## Guidance` section only on the next scan. Accepted
rather than threading a graph connection into the ingest tail.

## Plugin parity

One doc line in `plugins/graph-wiki/agents/ingestor.md` (step 10, "Update
index"): when writing guidance pages manually, also refresh
`guidance/index.md` and the affected `guidance/<topic>/index.md`. The
Bedrock/CLI backend gets regeneration for free via `update_index()`.

## Testing

- **wiki-io units** (new test module or extend the update_index tests):
  - empty / absent `guidance/` → no files written
  - single topic → root + topic index contents (banner, links, counts)
  - multiple topics → alphabetical topic order, per-topic title sort
  - impact suffix present/absent; summary present/absent
  - topic display-name derivation (`deep-agents` → "Deep Agents")
  - topic dir containing only `index.md` → skipped, not listed in root
  - re-run idempotence (second run produces identical content modulo the
    `updated` date)
- **guidance-io unit:** `list_pages` excludes `index.md`.
- **index_generator units:** `## Guidance` section renders with per-topic
  links + counts; section omitted when no guidance pages; section ordering
  (after Sources, before Work).

## Out of scope

- Garbage-collecting stale index files for deleted topics.
- Including guidance in the main index's curated-page count or as a full
  curated lane.
- Regenerating the main index from the ingest tail.
- Any change to the guidance page schema or the skill-ingest writer.
