# Test Audit — 2026-07-05

## Executive Summary

The workspace's 15 packages (including `root`) carry **3,408 test functions across 351 test files**. A first-pass agent fleet scanned every package and flagged **124 removal/merge candidates**. A second, skeptical per-package reviewer re-checked each candidate against the actual production source and confirmed **107 candidates** as genuinely safe to action (a ~86% confirmation rate) — the remaining 17 were downgraded back to "keep" as false positives, i.e. tests that turned out to protect real regressions. The 107 confirmed candidates span **144 individual test functions**: **102 recommended for outright removal** and **42 recommended for merging/consolidation** (near-duplicate tests folding into a stronger sibling). Applying every confirmed candidate would shrink the suite by roughly **144 tests out of 3,408 (~4.2%)**. `graph-wiki-core` (816 tests) contributes the largest single share of confirmed candidates (44 test functions, 28 candidate rows), but even there the affected share is only ~5.4% of the package's own suite — this is a broad-but-shallow trim, not a deep cut into any one package's coverage.

## Methodology

This was a two-pass, LLM-driven audit, not a human review:

1. **Analyze pass**: an agent fleet scanned each package's test files and flagged 124 removal/merge candidates against heuristics (rename artifacts, redundant/duplicate assertions, low-utility scaffolding, overlapping coverage, trivial dataclass/literal checks).
2. **Adversarial verify pass**: a second, skeptical reviewer went candidate-by-candidate, per package, re-reading the actual production source each test claims to protect (not just the test code) to check for hidden branching, unique invariants, or coverage gaps the first pass missed. This pass rejected 17 of 124 candidates as false positives — genuine regression protection the first pass had misjudged as redundant — and confirmed 107 as safe, in several cases downgrading a "remove" recommendation to "merge" where a narrow, real slice of coverage was worth preserving in a consolidated test (e.g. `test_role_sweep.py`'s dispatch-routing tests, `source-parser`'s `ValueError`-hierarchy check).

**This report does not delete or modify any test.** It is a recommendation artifact only. Before acting on it: a human should spot-check at least the high-impact and merge-flagged entries above (especially in `graph-wiki-mcp`, `model-adapter`, and `graph-wiki-core`, which have the highest affected-percentage or absolute-count), confirm the cited line numbers/source behavior still hold at HEAD, and run the full per-package suite after each batch of deletions to catch anything the audit missed.
