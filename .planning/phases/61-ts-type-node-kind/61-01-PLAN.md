## Task 2: Emit `type` nodes from the generic walker

<read_first>
- packages/source-parser/src/source_parser/parsers/_generic.py
- packages/source-parser/src/source_parser/tree.py
</read_first>

<action>
1. Add a helper `_ts_kind_for(node_type: str) -> str` (or inline mapping) that maps the
   tree-sitter declaration node type to a `ts_kind` value:
   `interface_declaration` → `"interface"`, `type_alias_declaration` → `"type_alias"`,
   `enum_declaration` → `"enum"`.
2. Add `_build_type_node(node, source, config, parent_path) -> SourceNode` that returns
   `SourceNode(kind="type", name=<name>, path=parent_path+(name,), attrs={"ts_kind": _ts_kind_for(node.type)})`.
   Use `_name_of` for the name (fallback `"<anonymous>"`).
3. In `_walk_container`, add a branch BEFORE the catch-all recurse:
   `elif node_type in config.type_types: results.append(_build_type_node(child, source, config, parent_path))`.
4. In `_handle_export` (the `export_statement` peek), add a matching branch so
   `export interface Foo` / `export type Bar` / `export enum E` emit a `type` child:
   `elif child.type in config.type_types: results.append(_build_type_node(child, source, config, parent_path))`.
</action>

<acceptance_criteria>
- A bare `interface Foo {}` parses to a node with `kind == "type"` and `attrs["ts_kind"] == "interface"`.
- An `export interface Foo {}` ALSO emits a `kind == "type"` node (the export peek branch fires).
- `type Bar = string` → `ts_kind == "type_alias"`; `enum E { A }` → `ts_kind == "enum"`.
- Class and function extraction behavior is unchanged (no regression to `_build_class_node` / `_build_function_node`).
</acceptance_criteria>

## Task 3: Thread `symbol_kind` through export References

<read_first>
- packages/source-parser/src/source_parser/parsers/_generic.py
- packages/source-parser/src/source_parser/tree.py
</read_first>

<action>
In `_extract_exports`, when an exported declaration is a class / function / type, stamp
the symbol kind onto the emitted `Reference` via `attrs`. The current loop matches
`desc.type in config.function_types or desc.type in config.class_types` and resolves the
name via `_resolve_name`; extend it to also match `desc.type in config.type_types`, and
record which kind matched so the per-name `Reference` can carry it:
- class declaration → `attrs={"symbol_kind": "class"}`
- function declaration → `attrs={"symbol_kind": "function"}`
- type declaration (`type_types`) → `attrs={"symbol_kind": "type"}` (resolve its name via
  `_resolve_name`, mirroring the class/function name resolution).
Bare re-exports (the `export-clause` / `identifier` fallback `walk()` branch that fires
when no declaration is found) CANNOT know the symbol kind at parse time — leave those
emitted references WITHOUT a `symbol_kind` attr (the projection default of `function` +
graph-io cross-kind sweep resolves them). Do not change the `Reference` dataclass
(`attrs: dict` already exists in `tree.py`).
</action>

<acceptance_criteria>
- An export of `interface Foo` yields a `Reference(kind="export", target_name="Foo", attrs={"symbol_kind": "type"})`.
- An export of a class yields `symbol_kind == "class"`; of a function, `symbol_kind == "function"`.
- A bare `export { foo }` yields a `Reference` whose `attrs` has no `symbol_kind` key.
</acceptance_criteria>

## Task 4: Fix the projection export-edge destination kind

<read_first>
- packages/source-parser/src/source_parser/projections/graph.py (the `_walk` function — specifically the `ref.kind == "export"` branch which currently emits `dst=("function", ref.target_name, None)`; and `_emit_node` which already copies `dict(node.attrs)`)
</read_first>

<action>
In `graph.py` (the `_walk` ref-emission loop reached via `to_graph_records`), change ONLY
the `ref.kind == "export"` branch dst from
`("function", ref.target_name, None)` to
`(ref.attrs.get("symbol_kind", "function"), ref.target_name, None)`.
LEAVE the `ref.kind == "call"` and `ref.kind == "import"` branches exactly as they are
(calls/imports keep their existing hardcoded dst per the locked decision). NOTE:
`_emit_node` already does `attrs=dict(node.attrs)`, so `ts_kind` flows from the parsed
`SourceNode` to the projected `GraphNode` with no edit needed there.
</action>

<acceptance_criteria>
- For an export ref with `attrs={"symbol_kind": "type"}`, `to_graph_records` produces an
  edge with `kind == "exports"` and `dst == ("type", "<name>", None)`.
- For an export ref with no `symbol_kind`, the exports-edge dst kind defaults to `"function"`.
- The `calls` edge branch still emits `dst[0] == "function"` (unchanged).
- `to_graph_records` emits a `GraphNode` with `kind == "type"` and `attrs["ts_kind"]` preserved for a parsed type SourceNode.
</acceptance_criteria>
