# Milestone v1.11: TypeScript Type Node Kind

**Status:** ✅ SHIPPED 2026-05-31
**Phases:** 61 (single phase)
**Total Plans:** 3

## Overview

Surfaced TypeScript `interface`, `type alias`, and `enum` declarations as a single
new `type` node kind (with a `ts_kind` sub-kind attribute) across `source-parser` and
`graph-io`, fixing the projection bug that previously mislabeled exported types as
`function`. The milestone was originally opened as "Cost-Frontier Sweep Harness"
(Phase 60); that work was deferred and the milestone was repurposed around the
TypeScript type-node work as its only phase.

## Phases

### Phase 61: TypeScript `type` Node Kind

**Goal**: Surface TS `interface` / `type alias` / `enum` declarations as a single new
`type` node kind (sub-kind in the `ts_kind` attr) in source-parser + graph-io, fixing
the projection bug that mislabels exported types as `function`.
**Depends on**: — (v1.10 graph/wiki foundation)
**Plans**: 3 plans (sequential dependency chain, one per wave)

Plans:

- [x] 61-01: source-parser — TS `type` extraction + projection export-kind fix
- [x] 61-02: graph-io — cross-kind resolution for `type` + DERIVER_VERSION bump
- [x] 61-03: tests + fixtures + mono-repo-live verification

**Details:**

- **61-01** — Added `LanguageConfig.type_types` (TS config: `{interface_declaration, type_alias_declaration, enum_declaration}`; JS empty). `_build_type_node` emits `SourceNode(kind="type", attrs={"ts_kind": ...})` for all three constructs, bare and exported. `_extract_exports` stamps `symbol_kind` (`class`/`function`/`type`) on declaration exports; the graph projection `exports` edge dst now uses `ref.attrs.get("symbol_kind", "function")` instead of a hardcoded `"function"` (the `calls` edge is unchanged).
- **61-02** — Added `type` to graph-io cross-kind resolution (`_CROSS_KIND_RESOLVABLE` set + the inline `kind IN (...)` SQL), bumped `DERIVER_VERSION` 4→5 (auto-forces a full rebuild on existing graphs; `SCHEMA_VERSION` unchanged at 2 — `kind` is unconstrained TEXT), and added `type` to `queries._VALID_KINDS` so `cg find --kind type` no longer raises.
- **61-03** — Added 7 source-parser TS fixtures (bare/exported interface, type alias, enum) with paired expected JSON, 2 graph-io cross-kind resolve tests, and a `_VALID_KINDS` assertion. Full mono-repo-live rebuild (DERIVER 5) confirmed `APIGatewayProxyEvent` resolves to `kind=type` (was `function`). Mid-flight Rule-1 fix: detected `export type { X }` re-export syntax and stamped `symbol_kind=type`.

## Milestone Summary

**Decimal Phases:** None.

**Key Decisions:**

- Single `type` node kind with a `ts_kind` sub-kind attribute (interface / type_alias / enum), rather than three distinct kinds — keeps the graph ontology compact while preserving the distinction in `attrs`.
- `kind` column left as unconstrained TEXT (no schema migration); only `DERIVER_VERSION` bumped to force re-derivation.
- `symbol_kind` carried on export References only for declared exports; bare re-exports rely on the projection default (`function`) + graph-io's single-candidate cross-kind sweep.

**Issues Resolved:**

- Exported TS types were projected as `function` nodes (root cause: hardcoded export-edge dst kind in `source-parser/projections/graph.py`).
- `export type { X }` re-exports were not stamping `symbol_kind` (fixed during 61-03 live verification).

**Issues Deferred:**

- WR-01 (code review): inline per-specifier `type` modifiers (`export { type Foo, bar }`) are not detected; `Foo` is mis-kinded as `function` (partially self-corrected by the cross-kind sweep). Documented v1 gap.
- Cost-Frontier Sweep Harness (former Phase 60) — sweep run + winner selection parked in `.planning/CONTINUE-sweep-harness-fixes-3.md` for a future milestone.

**Technical Debt Incurred:**

- `APIGatewayProxyEvent` and other out-of-tree (`node_modules/@types/...`) types resolve to `kind=type` but carry no `ts_kind` (no in-tree declaration to parse) — acceptable: the core goal (not mislabeled as `function`) is met; in-tree types carry `ts_kind` correctly.

**Verification:** 8/8 must-haves verified. Code review: 0 blockers, 3 warnings, 3 info (advisory). Package suites green (source-parser 92, graph-io 511); regression suites green (wiki-io 385, workspace-io 87).
